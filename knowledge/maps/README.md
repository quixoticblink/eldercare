Individual entries in this wiki describe *things* — a meeting, a partner, an HMW iteration, a research finding. Individual entries don't easily show how those things *relate*. This folder holds the connective tissue: chronological, actor-oriented, and cross-cutting views that make the wiki navigable when it's grown past what a single reader can hold in their head.

Think of `maps/` as *"the atlas."* Every other folder is a country; this folder is where you find the world map, the political relationships, the trade routes, and the timeline of events.

Each map is a view over the wiki, not a copy. When individual entries change, the map's summaries and pointers may drift — the maps are dated and should be updated when they no longer match reality. The full-fidelity source-of-truth is always the individual entry the map points at.

## What lives here

- **[[timeline]]** — the sprint's chronological arc, from Day 1 (2026-05-19) to Demo Day. Every journal entry threads onto this timeline plus the milestones between them. Read this first if you want to understand *how the thinking evolved.*
- **[[actors]]** — the ecosystem map. Who's on our team, who's a partner (NCSS, AIC, Vanguard, Care Corner), who's a competitor (Luce, Homage, Jagami), who convenes us (SGLN, SUSS), and how they relate to each other. Read this if you want to understand *the political geography.*
- **[[hmw-evolution]]** — the HMW's journey from broad companionship to caregiver-activated respite. Five iterations, four narrowings and one deliberate widening, with the evidence that moved us at each step. Read this if you want to understand *why the question changed.*
- **[[rubric-and-folders]]** — the four-part SGLN rubric mapped against the wiki's folder structure. Which folder feeds which rubric line. What's currently thin, what's currently overfed. Read this if you want to understand *what the wiki is optimising for.*
- **[[proposed-stubs]]** — the registry of dangling `[[wiki-links]]` that don't yet have entries. Ranked by inbound-link count so future writing can target the highest-leverage gaps. Read this if you want to know *what to write next.*

## What doesn't live here

- Substantive claims about the problem, the partners, or our solution — those live in `problem/`, `landscape/`, `strategy/`, `evidence/`, `humans/`, `reframing/`.
- Meeting records — those live in `journal/`.
- Raw sources — those live in `evidence/sources/` and `artifacts/`.
- Field photos — those live in `images/`.
- The style guide — [[../VOICE]].
- Project orientation — [[../purpose]].
- The wiki-wide index — [[../README]].

The distinction: substantive files answer *"what do we know?"* Maps answer *"how does what we know fit together?"*

## Maintenance rule

Every map file has a `last_updated` date in its front matter. If you touch a substantive entry in a way that changes the *shape* of the wiki — a new HMW iteration, a new partner, a new evidence stream, a new strategic decision — update the relevant maps in the same pass. If a map's `last_updated` is more than a month behind the substantive entries it summarises, treat it as stale until reviewed.
