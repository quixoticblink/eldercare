The biggest single ask from the eight seniors on Aug 21 was the one we had deliberately
left in Bucket 3: the app in Mandarin. It went out the same evening as v1.6. Caregiver
and kaki screens only — the coordinator console stays English by design. The plan we
executed is [[../prototype/plans/v1.7-language-switch]]; what shipped is `app/SPEC.md`
§7 and §10, and the reader's version in [[../prototype/roadmap]].

## The arc of the evening

- Wrote the plan, six tasks: dictionary and toggle; sign-in and waiting screen;
  caregiver screens; kaki screens; notifications and the help bot; a Chinese lifecycle
  test that fails on any English label. Each task started with its failing test.
- The mechanism is small on purpose. One file, `frontend/js/i18n.js`, about four hundred
  ids in English and Chinese; `UI.t("id")` picks the sentence, `UI.v("service", value)`
  picks a display name while the value underneath stays English. The frontend has no
  build step, so that is the whole of it. The four views now contain no literal English.
- The backend learned three things: a `users.lang` column so the choice follows the
  person and decides the language of their SMS; a stable `error` code next to the
  English `detail` for the ten errors a senior can actually hit (wrong code, expired
  code, too many tries, wrong kaki code, wrong start code, window passed…); and a Chinese
  keyword table for the help bot, used when the question itself is Chinese.
- Two review passes. Then backup, rsync, two restarts, and a production check without
  signing in: the toggle, the Chinese sign-in screen, the help bot answering 什么是开始码？
  in Chinese, and back to English.

## What we learned

- **The server's record wins on a shared phone.** The first version let the phone's
  stored choice override the account's. Fine for one person, one phone. At an AAC a
  kaki and a caregiver may sign in on the same borrowed phone, and the kaki's 中文 would
  have silently switched the caregiver's SMS to Chinese. The second reviewer caught it;
  the fix is a one-line reordering, plus the rule that only an explicit choice is
  written back — the phone's own language is a default, not a decision. Four of our
  own tests had encoded the wrong rule, which is worth sitting with: a test proves the
  behaviour you thought of, not the one you didn't.
- **Reviews find what tests cannot, again.** Names had been reaching email bodies
  unescaped since v1.4; the reason on a cancellation was HTML-escaped into the SMS
  ("Mum&#x27;s unwell"); the Chinese assignment message carried an English sentence from
  `assumptions.json`; the help bot's keyword table matched 验证码 (the sign-in code)
  before Kaki 验证码 (the door code). None of these is a test failure. All four are what
  a person would notice in the first hour.
- **Glossary before dictionary.** Deciding once that *Kaki* stays Kaki, that the start
  code is 开始码 and the kaki code is Kaki 验证码, made four hundred strings consistent
  and let the reviewer check them against a list instead of a feeling. The first draft
  had used 验证码 for both codes on adjacent screens.
- **Translate the label, never the value.** Every chip carries the English value in
  `data-v` and the Chinese label in its text. A caregiver who books 陪伴 sends
  `Companionship`; the coordinator's console, the matcher and the audit log never see a
  Chinese word. The e2e test asserts both ends of that.
